# T-001 — Markdown link checker (example app)

## Goal

A writer can run one command over Markdown files or folders and get the list of inline links whose relative
target does not exist, with file and line, and an exit status a script can test. The app is the kit's worked
example: it is planned, built, reviewed and merged through the gate, so a reader can follow one task end to end.

## Spec

[`example/linkcheck/SPEC.md`](../example/linkcheck/SPEC.md)

## Owns

The path globs the worker may change. They must equal the `owns` the task was created with in the store.

- `example/linkcheck/**`

## Acceptance criteria

Number each criterion and say how it is checked, by a named test or by a command and its expected output.

1. AC1: A broken relative link, with or without a `#fragment`, is reported on standard output as
   `<file>:<line>: <target>`, in argument, file and line order, with exit status 1; an existing file with a
   fragment is not reported. Checked by: `test_broken_relative_link_is_reported_with_file_and_line`,
   `test_fragment_is_ignored_when_resolving`, `test_output_follows_argument_then_line_order` in
   `example/linkcheck/tests/test_linkcheck.py`.
2. AC2: Targets starting with `http://`, `https://`, `mailto:` or `#` are never reported and no network
   connection is attempted. Checked by: `test_skipped_targets_are_not_reported_or_fetched` in
   `example/linkcheck/tests/test_linkcheck.py`.
3. AC3: When every link resolves, or there are none, the output is empty and the exit status 0; no PATH, or a
   PATH that does not exist, gives exit status 2, empty standard output and a message on standard error. Checked
   by: `test_all_links_resolve_exits_zero_without_output`, `test_no_path_is_a_usage_error`,
   `test_missing_path_is_a_usage_error` in `example/linkcheck/tests/test_linkcheck.py`.

## Edge cases

- A target is resolved relative to the directory of the linking file, not the current directory:
  `[up](../README.md)` in `docs/guide.md` passes when `README.md` sits beside `docs/`, and `[x](README.md)` in
  `docs/guide.md` is reported even when the current directory holds a `README.md`. Checked by:
  `test_target_resolves_relative_to_linking_file`.

## Out of scope

- Reference-style links, images, autolinks and HTML links.
- Checking anchors inside files.
- Ignoring links inside fenced code blocks or inline code.
- Absolute paths, other URL schemes, link titles, angle-bracket targets, percent-encoding.
- Any change outside `example/linkcheck/`, including the gate itself.

## Checks

The exact commands the worker runs, and passes, before moving the task to review.

- `python -m unittest discover -s example/linkcheck/tests`
- `python -m unittest discover -s gates/tests`

## Escalate when

Stop and escalate, with `transition <id> escalated`, when any of these happens:

- A decision is needed that this contract did not make.
- A change is needed outside the paths in Owns.
- A check cannot pass without weakening a test or an assertion.

`not applicable` and `deferred` (case-insensitive). A `deferred` row needs a note that says what is left and why.
